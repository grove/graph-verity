# NL Ask draft v1

Issue [#72](https://github.com/grove/graph-verity/issues/72) adds a model-free,
strict proposal boundary to [Confirmed Ask v1](confirmed-ask.md). It does not
connect a model, implement retrieval or add an execution endpoint. Historical
ParserResponse v1 and compact-v2 contracts are unchanged.

The separate [JSON schema](../schemas/nl-ask-draft-v1.json) is generated by
`verity schema-nl-ask` and checked against Rust. A candidate is exactly:

```json
{"version":"nl-ask-draft-v1","status":"candidate","start":100,"predicate":1000,"graph":0,"direction":"forward","output":"values","rationale":"Short interpretation to review"}
```

The alternative statuses are `needs_clarification` and `unsupported`, with only
`version`, `status` and `rationale`. Rationale is required, 1–512 Unicode
characters, **untrusted display text only**: render as text, never HTML or
instructions. Draft input is at most 16 KiB. Unknown/duplicate fields, unknown
versions, omitted direction/start/graph, IRIs in ID fields, raw SPARQL, answers,
filters, counts and model-supplied limits/policy/scope/snapshot/approval fail.
No invalid reply is repaired.

The trusted host builds `CatalogSelection` from its frozen retrieved candidate
tables. Entity/predicate IDs have separate namespaces and an explicit graph ID;
graph IDs map to exact IRIs. Tables contain at most 64 entities and 64 predicates
across at most eight authorized graphs. `freeze_nl_ask_catalog` validates graph,
role and observed-resource membership against an authorized immutable discovery
index, including source provenance and policy identity. Unknown sources and
cross-graph role borrowing fail. The opaque Context cannot be deserialized or
mutated. Its source-index hash records the source/table boundary.

The host must independently set `resolved_start` to one exact entity ID after
resolution; `null` prohibits a candidate. Alias collisions, no matches and missing
named constants must not be resolved by selecting the first ranked hit. The model
must echo that exact ID. `blocked` records a **host preflight** decision, such as a
known unsupported request; it is not model abstention and makes no claim that Rust
understands free text. The compiler cannot recognize unflagged language negation,
missing extra constraints or a semantically wrong direction. Those failures need
separate semantic scoring and user review.

`preview_nl_ask` expands a candidate into one existing `AskRequest v1`: exactly
one authorized graph, exact observed start/predicate, one directed step, terminal
`values`, `filter: null`, and operator-chosen limit 1–100 within policy. Snapshot,
policy row/evidence/time caps and approval digest are supplied by the host or
existing compiler. Policy or snapshot changes fail closed. Clarification and
unsupported drafts produce no AskRequest or preview. Candidate previews invoke
`Snapshot.preview_ask`; they never query for answer bindings. The authoritative
Rust preview is separate from the model rationale and leaves interpretation
correctness unassessed.

The CLI adapter is preview-only:

```sh
verity nl-ask-preview RDF nquads POLICY SCOPE DISCOVERY_CONFIG CATALOG DRAFT
```

`CATALOG` is trusted operator JSON matching `CatalogSelection`; it includes the
snapshot, graph/entity/predicate tables, resolved start, blocked flag and limit.
`SCOPE` and source config use the existing discovery boundary. Output includes
`request`, the existing confirmation-bound `preview`, and `display_rationale`.
Only the existing Confirmed Ask flow can execute the expanded request, after
independent exact-plan approval. Cancellation and stale approval never execute.

See the [60-case preregistration](../studies/nl-ask-v1/README.md) for the frozen
bilingual split, source audit, scoring taxonomy, numerical gates and human-review
limitations. These curated catalogs are contract fixtures; question-only
retrieval and inference remain follow-up work in #73 and #74.
