# V1g: distinguish retrieval coverage from interpretation

This is a separately versioned **design preregistration**, not an executable
native freeze or inference authorization. Its registration binds this protocol,
the measured v1f analysis, original source/reference bytes and #82's existing
packet evidence. The final adapter, numeric packet binding and model contexts must
be materialized, tested and committed in a separate execution registration before
any v1g inference. No v1g run command currently exists.

The primary comparison uses all 30 exposed questions in three conditions for
each pinned model. Two oracle repetitions plus 90 condition observations give
92 observations; native sampling controls bring the maximum to **94 completion
requests/model**, one serial attempt, no retries. The fixed condition order can
confound cache/time with condition, so report timings descriptively. Repeats are
separate diagnostics, excluded from the 18-supported primary endpoint.

Use the same source-language, collision and source-usage renderer in all three
conditions, with transport packets retained outside prompts. Only graph-qualified
membership varies. Freeze the rendered bytes before native generation. This is a
new controlled comparison, not a rerun of v1f or an estimate of how neighborhood
would have changed historical responses. A later experiment with full v2 packet
witness presentation would test another factor and needs a separate registration.

The v2 bridge must revalidate original packet bytes and bind drafts to packet IDs
using the existing Rust NeighborhoodContext API. Every allowed original numeric
catalog ID must map to the same graph/IRI/role. Include all retained candidates;
never choose a start from rank, insert an expected predicate, restore a missing
BM25 ID or put reference plans in prompts. Operator resolution/block fixtures
remain post-generation validator inputs, separately identified as AI-authored.

## What the existing evidence establishes

V1f has no observed model failures: all 72 observations are unattempted because
operator authorization is absent. At 2026-10-19 10:03:32 UTC the native host also
failed swap: 2,330.88 MiB versus 1,024 MiB maximum. Assets and the original binary
verified; neither authorization nor a passing future gate follows from that.

The earlier v1e experiment has 17 completed native responses, all in oracle
controls. Qwen over-clarified the explicit rdfs:label request with the necessary
entity/predicate available. Its two country rationales also named contradictory
predicate identities. Gemma's ambiguous-location candidate was rejected by Rust.
Neither completed the six smoke cases or retrieval comparison. These are real
interpretation/ambiguity observations, with no complete model ranking and no
claim that retrieval caused those failures.

#82 separately measured required predicate coverage **6/18 for BM25-v1 versus
18/18 for neighborhood-v2** at k=20. Every one of the twelve BM25 misses lacked
matching whole-question predicate lexical tokens; source adjacency recovered
all twelve. This establishes a coverage mechanism, not a model interpretation
benefit. Both methods still return candidates on 12 clarification/unsupported
requests. More vocabulary can also add distractors and encourage guesses.

The v1f source audit and mechanically enumerated source statements show a second
limit: **all predicate text lists are empty**. P17, P131 and P856 occur as edge
identities, but the original source supplies no descriptive predicate metadata
establishing their requested natural-language meanings. Local names, object type,
usage and an AI reference are insufficient substitutes. Treat this as a distinct
source-meaning limitation even if a model matches a reference from prior knowledge.
No inference data currently determines which limit will dominate v1g.

## Test predicate meaning explicitly, without inventing it

First add model-free, mechanically generated **explicit-predicate tests** in a
separate development fixture: for every permitted graph/predicate, take sorted
original subject/object witnesses and ask for values using its explicit full
predicate IRI in forward and reverse wording. Apply the same rule to every
predicate and preserve empty-path cases separately. Construct contexts from source
and retrieval alone, then derive reference fields/witnesses after prompt sealing.
These tests measure ID/role/direction binding without requiring a translation of
P17/P131/P856. They are not natural-language understanding or pristine holdout
evidence. No model-generated query needs execution to compare typed plan fields.
The explicit-predicate test panel is not part of v1g's 30-question denominator;
register its exact new questions and bound requests separately before inference.

If natural-language meaning remains the bottleneck, preregister a **later metadata
enrichment experiment**, independently from the retrieval factor. An operator
would retain an official, licensed source revision containing explicit predicate
labels/descriptions and an explicit directClaim association to each used direct
predicate IRI. For W3C/Schema vocabularies, retain the applicable official metadata
and exact IRI association as separate source evidence. No metadata is fetched or
asserted here. Before use, require immutable archive hashes, exact literal text,
language/datatype, source URL/revision/license, graph-qualified association and
machine checks that the quoted triples really occur. Apply a fixed allowlist/rule
to all permitted predicates, not just reference-required IDs. Missing metadata
stays missing; a foreign graph's label never silently defines a local identity.

Use a new source/packet revision and compare original versus enriched vocabulary
with retrieval held fixed. Publish the imported definitions verbatim with their
provenance, rather than asking an AI to write glosses. Independent source backing
means a real retained source supplies the claim; it does not turn exposed AI
reference plans into independently validated natural-language judgments.
