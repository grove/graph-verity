**INCONCLUSIVE_REVISE**; independent human semantic review is deferred. The
[unattempted score](unattempted-score.json) preserves every scheduled request
with missing semantic measurements, rather than manufacturing successful outcomes.

Construction asks the original 60 mechanical questions with explicit start,
predicate and graph IRIs. Their source-derived comparison fields are independent
of the model and of natural-language relation interpretation. The panel has
17 witnessed and 17 empty forward paths, and nine witnessed and 17 empty reverse
paths. Literal objects are never converted into entity starts. A failure to emit
the correct five fields on a fully supplied explicit request is evidence of a

twelve questions have abstention references. These strata are recorded in the
score. Both arms receive exactly the same system prompt, question, names,
original usages, graph-qualified IDs, collision warnings and grammar; only the
source metadata arrays change. The arms use distinct host packet identities.
No explicit-IRI treatment enters this paired comparison. The 60 construction
questions are a separate diagnostic, not a baseline score for these questions.

Norwegian property text, ambiguous graph wording, absent entity labels and
exposed-AI-reference tensions remain potential limits even with enrichment.

## Compiler compatibility is a third observable boundary

[model-free-replay.json](model-free-replay.json) retains 124 **synthetic**
reference objects and their exact Rust preview results: 114 accepted and ten
rejected. Every object agrees with its original comparison fields. The ten
rejections are reverse empty paths: explicit-003, 006, 013, 020, 028, 035, 038,
042, 049 and 056. The compiler's unchanged predicate range checks prohibit an
IRI object for these literal-only predicates. NL Ask surfaces that failure as
`deterministic_preflight_block`. No candidate RDF query was executed.

Those ten source-derived mechanical requests remain in the 60-case construction
denominator. Their field fidelity can succeed while Rust compatibility fails.
They must not be reported as model construction failures merely because Rust
rejects them, nor silently removed or relabeled as successful abstentions. The
pre-existing references and compiler are unchanged. Conversely, a wrong-direction
candidate can be Rust-accepted while failing the expected direction field.
This compatibility qualification was observed model-free after registration,
before any generation; it changes no scoring rule or model input.
